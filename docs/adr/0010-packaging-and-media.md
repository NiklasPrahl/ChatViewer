# 0010 – Packaging, bundled CLI and media playback

- Status: Accepted
- Date: 2026-11-02

## Context

M5 turns the app into installable, unsigned builds for macOS, Windows and
Linux, with the `chatviewer` CLI included (architecture §9). It also has
to play WhatsApp voice notes (Ogg Opus), which some system WebViews
cannot decode.

## Decision

- **Bundles:** `tauri build` with `app/src-tauri/tauri.release.conf.json`.
  - macOS: `.app` in a `.dmg`, Apple silicon. The Intel build is left
    out for now: cross-building libopus for it is unverified.
  - Windows: NSIS installer and MSI.
  - Linux: `.deb`, `.rpm` and AppImage, built on Ubuntu 22.04 for an older
    glibc baseline.

  The release configuration is separate, so ordinary builds and CI do
  not need the sidecar.
- **CLI:** built as a Tauri `externalBin` sidecar
  (`tools/release/prepare-sidecar.sh`).
  - macOS: `ChatViewer.app/Contents/MacOS/chatviewer`.
  - Windows: next to the app in the install folder.
  - `.deb`/`.rpm`: `/usr/bin/chatviewer`.
  - `ChatViewer cli <args>` forwards to it, for AppImages.

  Nothing is added to the PATH silently. The release notes show the
  one-line symlink for macOS.
- **Licenses:** bundles contain `LICENSE` (MIT),
  `LICENSES/AGPL-3.0-only.txt` (verified identical to gnu.org) and
  `THIRD_PARTY_LICENSES.txt`. The last one is generated by `cargo-about`
  for Rust crates plus a script for the npm packages in the UI. The About
  dialog shows the license situation (ADR 0001) and the notices.
- **Releases:** `.github/workflows/release.yml` runs on tags `v*`
  (draft release) and on manual dispatch (artifacts only).
  - Each bundle gets a `.sha256` file.
  - A smoke test runs the CLI from the bundle (or the installed `.deb`),
    imports synthetic WhatsApp and Signal archives, exports every Signal
    chat to CVA and reopens one export.
  - Builds are unsigned. The release notes explain Gatekeeper and
    SmartScreen.
- **Opus voice notes:** the UI plays audio natively first. On a decoding
  error it requests `as=wav`, and the backend decodes Ogg Opus with
  **libopus** (reference implementation, BSD-3-Clause, built from source
  by `audiopus_sys` with cmake) into in-memory WAV. Pure-Rust Opus
  decoders were too young (0.1) to rely on.
- **Development builds** compile dependencies with `opt-level = 2`, so
  real backups open at a usable speed.

## Consequences

- Building needs cmake (for libopus). It is preinstalled on GitHub
  runners and available via Homebrew or the system package manager
  locally.
- Signed and notarized builds, auto-update and an Intel macOS build are
  possible later. Each needs signing keys or more CI work.
